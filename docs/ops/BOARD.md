## 규칙
- **알아서 한다**: develop 커밋·push(스테이징 배포), 테스트, BACKLOG·TEST-LOG·문서 갱신, 마케팅 제안·문구 초안, 성장 계획서 수정.
- **GO를 기다린다**: ① main 머지(프로덕션 배포) ② 외부 게시·DM·메일 발송 ③ 돈 쓰는 결정 ④ 계획서·BACKLOG 밖의 새 기능 ⑤ 개인정보 처리방침 변경 ⑥ 데이터 삭제·되돌리기.
- **답 쓰는 법**: "답" 칸에 `GO` / `STOP` / `보류` 와 필요하면 한 줄 메모. 답이 비어 있으면 그 항목은 그대로 대기하고 나머지는 진행한다. 채팅으로 "2번 GO"라고 해도 된다.
- **동시 작업**: 메인 체크아웃은 사이클 전용. 기획·관리자 세션은 워크트리에서 문서만 고치고 rebase 후 push한다. 파일 주인은 CLAUDE.md 표를 따른다.
- **배포 시각 규칙**: 아래 "예정 일정"의 게시·방송 1시간 전부터는 GO가 있어도 main 머지를 미룬다.
