# PRD 원페이저 — 계정·저장 기반(플랫폼) 구축

작성 2026-09-24 · 상태: **초안(검토 요청)** · 대상: 서버가 터져서 도망친 곳에 낙원은 있나?

## 1. 왜 하는가
지금은 브라우저 토큰만 있는 익명 게임이라 게임이 끝나면 모든 것이 사라진다. 친구들과 반복해서 하다 보니
"우리가 만든 단어 세트", "지난 게임 그림", "늘 쓰는 설정", "같이 하는 사람들"을 **다음에도 이어서** 쓰고 싶다는
요구가 생겼다. 이걸 가능하게 하는 최소한의 기반(계정 + 영구 저장)을 먼저 깔고, 기능은 하나씩 얹는다.

## 2. 목표 / 비목표
**목표**
- 로그인 없이도 지금처럼 바로 플레이할 수 있다(게스트 유지). 로그인은 "저장"이 필요할 때만 요구한다.
- 소셜 로그인 한 번으로 내 프로필·단어 세트·그림·설정 프리셋·친구가 기기와 브라우저를 넘어 유지된다.
- 운영 비용 0원 유지(무료 티어 안에서), 배포 시 게임이 끊기지 않는 현재 구조 유지.

**비목표(이번 범위 아님)**
- 공개 매치메이킹·랭킹·랜덤 방 입장, 결제, 관리자 콘솔, 신고/차단 체계, 앱 스토어 출시.

## 3. 사용자와 핵심 시나리오
- **방장(호스트)**: 우리 모임용 단어 세트를 만들어 두고, 다음 모임에서 "불러오기" 한 번으로 시작한다. 설정 프리셋(라운드·시간·모드)도 저장한다.
- **참가자**: 게임이 끝나면 내가 그린 그림이 내 갤러리에 쌓인다. 프로필 사진을 올려 아바타로 쓴다.
- **모두**: 친구를 추가해 두면 방을 만들 때 친구 목록에서 바로 초대(링크 전송/알림)한다.

## 4. 범위와 단계 (기반 → 기능 순)
| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **P0 기반** | 소셜 로그인(Google, Kakao), 사용자 테이블, 게스트 토큰 ↔ 계정 연결, 서버에서 토큰 검증, 로그인 상태 UI(아바타 메뉴) | 로그인/로그아웃 후 새로고침해도 유지, 게스트로도 플레이 가능 |
| **P1 단어·프리셋** | 커스텀 단어 세트 CRUD(이름, 단어 목록, 공개/비공개), 방 설정에서 "내 세트 불러오기", 설정 프리셋 저장/불러오기 | 세트 20개·세트당 500단어 제한, 방장이 불러온 세트로 게임 진행 |
| **P2 그림 보관** | 게임 종료 시 로그인 사용자의 그림(ops→PNG)을 자동 저장, 내 갤러리 페이지, 최대 장수 제한(예: 100장) 도달 시 "다운로드 후 정리" 안내, 일괄 ZIP 다운로드 | 갤러리에서 보기/다운로드/삭제, 제한 초과 시 저장 전 안내 |
| **P3 프로필** | 프로필 사진 업로드(리사이즈 256px, 1MB 제한), 닉네임 기본값, 아바타로 반영 | 방 안 아바타에 사진 표시 |
| **P4 친구·초대** | 친구 코드/검색으로 추가, 요청·수락, 친구 목록에서 초대 링크 보내기(웹 푸시는 후순위) | 친구가 온라인이면 방 링크 알림 수신 |

## 5. 기술 방향 (제안)
- **Supabase(무료 티어)를 BaaS로 채택**: Auth(Google/Kakao/Apple 소셜 로그인 내장), Postgres(500MB), Storage(1GB, 프로필·그림 PNG), Row Level Security. 별도 인증 서버·DB 서버를 직접 운영하지 않아도 되고, 무료 범위가 이 규모에 충분하다.
  - 대안 검토: Render Postgres(무료는 30일 후 만료 → 부적합), Firebase(Kakao 로그인이 기본 제공 아님), 자체 Passport+Postgres(운영 부담 큼).
- **게임 서버는 지금 그대로**(Node + Socket.IO + Render Key Value). 소켓 접속 시 Supabase JWT를 함께 보내면 서버가 검증해 `userId`를 플레이어에 붙인다. 로그인 안 한 사람은 지금처럼 게스트 토큰.
- **데이터 모델(초안)**: `profiles(user_id, nickname, avatar_url, created_at)`, `word_sets(id, owner_id, name, words[], is_public)`, `presets(id, owner_id, name, settings jsonb)`, `drawings(id, owner_id, room_code, word, category, png_path, drawn_at)`, `friendships(user_id, friend_id, status)`.
- **클라이언트**: 여전히 순수 HTML/JS. 화면이 늘어나므로(갤러리·세트 편집·프로필) 라우팅이 필요해지면 그때 최소한의 해시 라우터를 넣는다. 전면 UI 개편은 P2 이후 별도 건으로 판단.

## 6. 성공 지표
- 로그인 사용자의 재방문(7일 내 다시 플레이) 비율, 단어 세트 재사용 횟수, 갤러리 다운로드 수.
- 운영: 월 비용 0원, 배포 중 게임 끊김 0건 유지.

## 7. 리스크와 대응
- **Kakao 로그인 심사**: 이메일 등 일부 동의 항목은 비즈 앱 전환이 필요할 수 있다 → 닉네임·프로필만 요구하는 최소 동의로 시작.
- **무료 저장 용량**: 그림 PNG(800×600 ≈ 30~80KB) 1GB ≈ 1.5만 장 → 사용자당 100장 제한 + 6개월 미접속 시 정리 안내.
- **소셜 로그인 도입으로 진입 장벽 상승** → 게스트 플레이를 그대로 두고 "저장하려면 로그인" 지점에서만 노출.
- **개인정보**: 수집 항목 최소화(닉네임, 프로필 사진, 소셜 ID). 개인정보 처리방침 페이지 필요.

## 8. 결정이 필요한 것(검토 요청)
1. 소셜 로그인 제공자: **Google + Kakao**로 시작? (Apple은 iOS 앱 출시 시)
2. 그림 보관 한도: 사용자당 **100장** / 넘으면 다운로드 안내 후 오래된 것부터 삭제 — 숫자와 정책 확인.
3. 단어 세트 공개 공유(다른 사람이 쓰기) 허용 여부 — P1에 넣을지, 나중에 할지.
4. Supabase 채택 여부(무료 티어, 한국 리전 없음 → 도쿄/싱가포르. 지연은 로그인·저장에만 영향, 게임 자체는 무관).
5. P0 착수 시점 — 모바일 최적화와 스테이징 정착 이후를 제안.
