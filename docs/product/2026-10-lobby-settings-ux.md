# 설계: 대기실 게임 설정 화면 정리 (방장)

작성 2026-10-02 (금) · 작성: 기획 세션 · 상태: **설계 승인(운영자 결정 10-02, 기획 세션)** · 크기: 중간(기능 세션 아님 — BACKLOG #18·#20·#19로 사이클이 소화)

## 1. 한 줄 요약 · 누구의 어떤 상황
방장의 게임 설정 화면을 **게임 길이 · 단어 · 난이도** 세 묶음으로 정리하고, 프리셋(짧게·보통·길게)을 없앤다. 자주 쓰는 설정은 늘 보이고, 가끔 쓰는 설정은 요약 한 줄만 보이다가 열어서 바꾼다.
- 누구: 친구 3~8명을 방에 모아 놓은 **방장**(폰·PC 둘 다). 참가자가 기다리는 동안 설정을 빨리 읽고 시작할 수 있어야 한다.
- 왜(운영자 10-02): 지금 화면은 설정이 성격별로 묶여 있지 않아 가독성이 떨어진다. 게임 길이 프리셋은 맨 위에, 그 값(라운드·시간)은 맨 아래 "세부 설정"에 있다. 프리셋이 길이와 힌트를 함께 바꿔서 힌트만 바꿔도 "직접 설정함"이 된다. 조작 방식(프리셋 버튼·스위치·칩·체크·접힌 선택 상자)이 제각각이고, 폰에서는 "게임 시작"이 맨 아래에 있다.
- 참고한 게임: skribbl.io는 선택 상자 7개를 평평하게 한 줄로 둔다([skribbl.io](https://skribbl.io/), 확인). Gartic Phone은 프리셋 위에 "Custom settings"를 둔다([공식 X](https://x.com/garticphone/status/1372640014132207623?lang=en), 확인). Jackbox는 설정을 성격별로 묶는다([공식 블로그](https://www.jackboxgames.com/streaming-moderation-accessibility-features-jackbox-party-pack-eight/), 확인). 이 설계는 프리셋 없이 **성격별 묶음 + 자주/가끔 구분**으로 간다.

## 2. 목표 지표
- 북극성(완료 게임 수) 기여: 방을 만든 뒤 게임 시작까지 막힘을 줄인다. 측정: 일별 `starts / rooms`(지금 있는 카운터)를 #19 배포 전 2주와 배포 뒤 2주로 비교한다 [잠정. 지금은 표본이 작아 방향만 본다].
- 설정 사용 패턴(#20에서 새로 셈): `starts_cat_some / starts`(기본 카테고리를 전부가 아니게 고른 게임 비율), `starts_custom / starts`(커스텀 단어가 있는 게임 비율). 월 1회 측정한다(BACKLOG "모니터링").

## 3. 규칙과 화면 (게임 규칙은 그대로, 방장 설정 화면만)
```
게임 설정 · 🔄 돌아가며 그리기 [← 모드 선택]
① 게임 길이                                  4명 · 약 12분
   라운드        − 3 +
   그리기 시간    − 80초 +
② 단어
   커스텀 단어    ○──   (켜면 그 자리에 입력칸 · 📂불러오기 💾저장 🔗방 링크 · 커스텀 단어만 쓰기)
   카테고리       전체 13개                         [고르기] ▸ 창
③ 난이도      후보 3개 · 힌트 2번 · 마지막 힌트 15초 전   [바꾸기] ▾ 그 자리에서 펼침
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[                 게임 시작                 ]   ← 화면 아래 고정 (시작 안내 글 포함)
```

| 묶음 | 늘 보임 (자주) | 열어서 바꿈 (가끔) |
|---|---|---|
| ① 게임 길이 | 라운드(한 명이 그리기는 "문제 수"), 그리기 시간, 제목 오른쪽 예상 인원·시간(지금 `estimateGame`). 한 명이 그리기는 맨 위에 출제자 선택 | – |
| ② 단어 | **커스텀 단어** 스위치. 켜면 그 자리에 입력칸·세트 도구·"커스텀 단어만 쓰기"(지금 동작 그대로) | **카테고리**: 요약 한 줄 + "고르기" → **창** |
| ③ 난이도 | 요약 한 줄 | 단어 후보 수 · 힌트 횟수 · 마지막 힌트 시점 → **그 자리에서 펼침**(처음엔 접힘) |

**조작 규칙**
- 선택 상자 대신 **− / + 버튼**과 가운데 값. 끝값에서는 그쪽 버튼을 끈다. 값 목록은 지금 선택 상자 그대로다: 라운드·문제 수 1~10, 그리기 시간 15·20·25·30~180초(10초 단위), 단어 후보 2~5개, 힌트 0~5번(0 = "없음"), 마지막 힌트 5·10·15·20·30·45·60초 전.
- **프리셋 없음.** `LENGTH_PRESETS`·"짧게/보통/길게" 버튼·"직접 설정함" 표시를 없앤다. 모드를 고를 때 들어가는 기본값(`MODE_PRESETS`: 돌아가며 3라운드·80초·힌트 2, 한 명이 그리기 5문제, 속도전 5라운드·25초, 이어 그리기 한 명당 20초·힌트 3)은 그대로 둔다.
- **"가끔" 항목은 A 방식(운영자 10-02)**: 칸이 많은 목록(카테고리 칩 13개)은 창으로, 숫자 세 칸(난이도)은 그 자리에서 펼친다.
  - **카테고리 창**: 지금 ⚙ 설정 창과 같은 틀(PC는 가운데 창, 폰은 아래에서 올라오는 시트). 제목 "카테고리 고르기", 칩 13개와 "모두 선택 · 모두 해제". 규칙은 지금 그대로다(처음엔 전부 켜짐, 마지막 하나는 못 끔, "모두 해제"는 첫 카테고리만 남기고 토스트). 누르는 즉시 반영되고 저장 버튼은 없으며 "닫기"로 닫는다. 포커스 복귀·Tab 트랩·대기실을 벗어나면 자동으로 닫힘은 불러오기 dialog(#14)와 같게.
  - 카테고리 요약: 전부면 "전체 13개", 3개 이하면 이름을 ` · `로 이어서(예 "동물 · 음식"), 그 밖은 "13개 중 5개". 커스텀 단어만 쓰고 단어가 후보 수 이상이면 카테고리 줄을 숨긴다(지금 규칙).
  - **난이도 펼침**: 처음엔 접힘. 접혀 있어도 요약 한 줄이 보인다. 한 번 펼치면 그 방에 있는 동안 `room:state`로 다시 그려도 접히지 않는다.
- **"게임 시작"은 화면 아래 고정**(폰·PC). 시작 안내 글("결과 화면을 보고 있는 사람이 있어요…" 등)도 함께 고정한다. "🖼 지난 게임 그림 갤러리"는 고정 영역 밖, ③ 아래 일반 흐름에 둔다.

**모드별 차이** (칸의 뜻을 바꾸지 않고 묶음 안에서 처리)
| 모드 | ① 게임 길이 | ③ 난이도 |
|---|---|---|
| 돌아가며 그리기 | 라운드 · 그리기 시간 | 후보 · 힌트 · 마지막 힌트 |
| 한 명이 그리기 | 출제자 · 문제 수 · 그리기 시간 | 후보 · 힌트 · 마지막 힌트 |
| 속도전 | 라운드 · 그리기 시간 | "힌트 없음 · 단어 자동" 한 줄, 바꾸기 버튼 없음 |
| 이어 그리기 | "한 명당 시간" 하나 + "문제 수 = 인원(n명)" 글 | 제시어 후보 · 최대 힌트(마지막 힌트 시점 숨김). 도움말은 지금 문구 |

**문구 일괄 변경 (운영자 10-02)**
| 지금 | 바꿈 |
|---|---|
| 우리만의 단어(쓰기) | **커스텀 단어(쓰기)** |
| 우리 단어만 쓰기 | **커스텀 단어만 쓰기** |
| 비방장 요약·토스트의 "우리만의 단어 n개", "우리 단어로(만) 출제", "…우리만의 단어에 넣었어요" | "커스텀 단어 n개", "커스텀 단어로(만) 출제", "…커스텀 단어에 넣었어요" |
| 스위치 아래 설명 "우리끼리 아는 단어로 문제를 내요" | 그대로(설명 문장) |
| 묶음 이름 "맞히기 난이도" | **"난이도"**(단어 후보 수는 맞히는 난이도와 무관하다) |
| "세부 설정", "게임 길이" 프리셋 | 없어짐 |

**방장이 아닌 사람**: 이번 범위는 아니다. 프리셋이 없어지므로 요약 칩의 "짧게/보통/길게/직접 설정" 칩 하나만 빼고, 문구 변경을 따른다.

## 4. 프로토콜·서버·클라이언트 영향
- 이벤트·설정 필드 변경은 **없다**(`room:settings` 그대로). 지표만 바뀐다: PROTOCOL.md "이용 지표" 절과 `server/metrics.js` 머리 주석에 카운터 2개를 추가한다(#20).
- 클라이언트: `public/index.html`(설정 패널 구조, 카테고리 창), `public/style.css`(묶음·− / + 버튼·아래 고정·폰), `public/client.js`(`LENGTH_PRESETS`·`matchPreset`·`presetSub`·`PRESET_NAMES` 제거, `renderSettings`·`readSettings`·`buildRoom`, 비방장 요약, 카테고리 창 열고 닫기).
- 서버(#20): `server/game.js` `game_started`에 `categories`(고른 개수, 0 = 전체) 추가, `server/metrics.js` `bumpsFor`에 `starts_cat_some`(전체가 아닐 때 1), `starts_custom`(커스텀 단어가 있을 때 1).
- 테스트: `test/browser.js`·`test/mobile.js`·`test/mobile-lib.js`·`test/auth.js`가 지금 문구·선택 상자를 찾는다(확인 필요: 셀렉터 목록). `npm test`·`npm run test:browser`·`npm run test:mobile` 셋 다.

## 6. 위험과 대안
- **카테고리 사용이 줄 수 있다**(창 안으로 숨기므로). → 월 1회 `starts_cat_some / starts`를 본다(BACKLOG "모니터링"). 30% 이상이면 ②에 칩을 다시 펼치는 안을 검토한다 [잠정 기준].
- **폰 키보드와 아래 고정 버튼**: 커스텀 단어 입력칸에서 키보드가 올라오면 고정 버튼이 입력칸을 가릴 수 있다. → 입력 중에는 고정을 풀거나 입력칸이 버튼 위로 스크롤되게 한다(builder 판단, 모바일 테스트로 확인).
- **다시 그리기 충돌**: `room:state`가 올 때마다 다시 그리므로 창·펼침 상태와 입력 중인 값이 덮어쓰이면 안 된다(지금 "입력 중엔 덮어쓰지 않음" 규칙 유지). 방장이 바뀌거나 게임이 시작되면 카테고리 창을 닫는다.
- 대인원·재접속·대역폭 영향 없음(클라이언트 화면만, 지표는 서버 로그 한 줄).
