# 설계: 이어 그리기 (릴레이) 모드

작성 2026-09-30 (수) · 작성: 기획 세션 · 상태: **설계 승인 대기** · 후보 번호: [GAME-MODES.md](../GAME-MODES.md) 1번
로드맵: [ROADMAP.md](../ROADMAP.md) 10월 제품 줄 "신규 모드 1건 설계" (구현은 11월)

## 1. 한 줄 요약 · 누구의 어떤 상황
**한 단어를 3명이 20초씩 이어 그리고, 나머지가 맞히는 모드.** 카톡방에서 모인 3~6명이 "누가 이상하게 이어 그렸냐"로 웃는 상황을 위한 것이다.
- 지금 모드는 출제자 한 명만 그리고 나머지는 기다린다. 이 모드는 **그리는 사람이 자주 바뀌어** 대기가 짧다. 3~4명 방에서 특히 좋다.
- 성장 단위(한 방)에서의 이유: ① 방장이 "이어 그리기 할래?"로 링크를 보낼 새 이유가 생긴다 ② 결과 그림이 공동 작품이라 **여러 명이 같은 그림을 저장·공유하고 싶어진다**(F5 갤러리 이미지).

## 2. 목표 지표
- 북극성(완료된 게임 수)에 기여하는 길: 소인원 방의 **체감 대기 시간을 줄여 한 판을 끝까지 하게 만든다**.
- 측정: `game_completed` 이벤트에 이미 `mode`·`players`·`turns`·`durationSec`·`bytesOut`이 있다. **새 지표 이벤트는 만들지 않는다.** 출시 뒤 2주간 `mode=relay` 완료 수와 `players` 분포, 같은 방의 재시작(`gamesPlayed`)을 classic과 비교한다. 기준값이 없으므로 목표 숫자는 `[측정 뒤 확정]`.

## 3. 규칙과 화면 (classic과 다른 점만)
| 항목 | 규칙 |
|---|---|
| 주자 | 한 턴에 **k명**이 차례로 한 구간(`legTime`초)씩 이어 그린다. 나머지는 채팅으로 맞힌다 |
| k 결정 | `k = min(relayLegs, max(2, n-2))` (n = 접속 인원, `relayLegs` 설정 2~4, 기본 3). n=3→2, n=4→2, n=5→3, n=8→3. 맞히는 사람이 n≥4에서 항상 2명 이상 |
| 주자 순서 | 참가 순서를 **한 칸씩 밀며** k명을 뽑는다. 4명이면 ABC→BCD→CDA→DAB. 한 라운드 = n턴, 모두가 한 라운드에 정확히 k번 그린다 |
| 최소 인원 | **3명**(주자 2 + 맞히는 1). 2명 방에서는 모드 카드가 비활성("3명부터 할 수 있어요"). 스테이징(`ALLOW_SOLO`)은 1명도 시작 허용 |
| 단어 | 첫 주자만 후보 3개에서 고른다(15초, 기존 choosing). 이후 **주자 전원이 처음부터 단어를 안다**(다음 주자가 구상할 수 있게) |
| 시간 | 이 모드에서는 `drawTime`이 **주자 1명당 시간**이다(카드 프리셋 20초, 15..180은 그대로). 턴 전체 = `drawTime × k`. 구간 경계는 고정이고 타이머는 끊기지 않는다 |
| 힌트 | classic과 같다(전체 시간 기준 `hints`·`hintEndAt`). 프리셋 hints 2 |
| 캔버스 | 같은 캔버스를 이어 쓴다. **전체 지우기·되돌리기는 자기 구간에 그린 것만** 지운다(앞사람 그림 보호). 지우개·채우기 덧칠은 허용 |
| 채팅 | 주자 전원(현재·지난·다음)은 "정답자 전용 채팅"으로 묶여 맞히는 사람에게는 보이지 않는다. "다리 그려 줘" 같은 조율이 가능하다. 주자는 정답 판정 대상이 아니다 |
| 점수 | 정답자: classic 공식(전체 남은 시간 기준). 주자: **각자 `round(200 × 맞힌 수 / 맞히는 사람 수)`**. 숫자는 출시 뒤 튜닝 |
| 종료 | 전원 정답 → 즉시 종료, 시간 끝 → 종료. `turnEnd`에 단어와 주자 이름 표시 |

**화면**
- 상단 띠: "🖍 ○○님 (2/3)" + 다음 주자 칩. 주자 아바타는 기존 출제자 강조를 그대로 쓴다.
- **내 차례가 되는 순간** 전체 화면 배너 "내 차례! 20초"와 진동(모바일). 내 구간이 끝나면 툴바가 잠기고 "다음은 ○○님".
- 주자인데 차례가 아닌 사람: 캔버스와 단어는 보이고 채팅은 "주자 채팅"으로 표시된다.
- 모바일: 기존 그리기·맞히기 배치를 그대로 쓰고, 차례가 오면 그리기 배치로 바뀐다(확인 필요: `data-role` 전환을 구간마다 해도 깜빡이지 않는지).

## 4. 프로토콜·서버·클라이언트 영향
**먼저 [PROTOCOL.md](../../PROTOCOL.md)를 고친다.**
- `settings.mode`에 `'relay'` 추가, `settings.relayLegs`(2..4, 기본 3) 추가. 서버 clamp.
- `game:drawing`에 `relay: { legIndex, legCount, legTime, relayIds[], drawerIds[] }` 추가. `word`는 **`relayIds` 전원**에게 포함.
- 새 이벤트 `game:baton { drawerId, drawerName, legIndex, legCount, legTimeLeft }` — 구간이 바뀔 때 방 전체. 서버는 앞 주자의 열린 획을 닫고(`draw:end` 중계) `drawerId`를 교체한 뒤 `room:state`를 보낸다. catch-up(재접속)에도 같은 정보를 보낸다.
- `room:state`: `drawerId`는 **현재 구간 주자**(기존 클라이언트 로직이 그대로 동작). `players[].isRelay`(이번 턴 주자 여부) 추가.
- `game:over.gallery[]` 항목에 `drawerIds[]` 추가(기존 `drawerId` = 첫 주자, 하위 호환). 그림 보관은 `drawerIds`에 내가 있으면 저장(PROTOCOL "로그인" 절 수정).
- 서버(`server/game.js`): `MODES`, `buildTurnOrder`/`nextTurn`(슬라이딩 주자 계산), `beginDrawing`(구간 타이머), `tick`(경계에서 `baton`), `handleDraw`(자기 구간 이전 ops 보호 — `legStartOps`), `allGuessed`·`endTurn` 점수(주자 제외·주자 점수), `handleChat`(주자 채널), 끊김·퇴장(주자 유예), 스냅샷 저장·복원(구간 상태 포함).
- 클라이언트(`public/client.js`, `style.css`, `index.html`): 모드 카드, 설정 라벨("그리는 시간 → 한 명당"), `isDrawer()`는 그대로 `state.drawerId` 기준(구간마다 자동 전환), 주자 단어 표시(`ui.word`를 `relayIds` 포함이면 받음), 바통 배너·상단 띠, 주자 채팅 스타일.
- 끊김 규칙: 구간 경계는 고정. 현재 주자가 끊기면 기존 `DRAWER_GRACE_MS`(15초) 동안 기다리고 돌아오면 남은 구간 시간만큼 이어 그린다. 유예가 끝나면 그 구간은 비워 두고 경계에서 다음 주자로 넘어간다. 주자가 퇴장하면 그 구간은 비워 두되, 주자 수가 모자라 맞히는 사람이 0이 되면 기존 `notEnoughPlayers`.
- 건드리지 않는 것: 캔버스 좌표·op 형식, 정답 판정, 힌트 계산, 인증.

## 6. 위험과 대안
- **3명 미만 방**: 모드 카드 비활성으로 막는다. 2명은 classic/blitz로 안내.
- **망치는 사람(트롤)**: 구간 보호(R2)로 앞 그림을 통째로 지우지는 못한다. 덧칠은 허용이라 웃음 포인트로 본다. 문제가 되면 "지우개 금지" 토글을 핸디캡 후보(GAME-MODES 7번)로 돌린다.
- **모바일 교대 순간**: 구간 끝에 손가락이 캔버스에 있으면 서버가 획을 닫고 이후 입력은 무시된다. 클라이언트는 `baton` 수신 시 열린 획을 닫는다(R3에서 확인).
- **재접속·새로고침**: 구간 상태를 스냅샷에 넣는다. 배포 중 게임 보호(새로고침 미루기)는 그대로.
- **대역폭(Render 5GB)**: op 중계량은 classic과 같다(같은 캔버스, 한 번에 한 명 그림). 갤러리 전송량도 같다. 추가는 `baton` 이벤트와 `relay` 필드뿐이라 무시 가능. 출시 뒤 `bytesOut`으로 확인.
- **점수 밸런스**: 주자 점수 200은 초안 숫자. 출시 2주 뒤 주자·정답자 평균 점수 차를 보고 조정한다. 측정은 로그가 아닌 운영자 관찰(지표에 점수를 남기지 않는다).
- **턴이 길어짐**: 4명·3구간·20초 기준 한 라운드 ≈ 4×(60+5)초 ≈ 4.3분. classic(80초×4)과 비슷. 라운드 수 프리셋은 2.

## 7. 운영자가 정할 것 (권장안대로 쓰였다. 바꾸려면 알려 주세요)
1. **단어 공개 범위** — A. 주자 전원이 처음부터 안다(권장, 협동·구현 작음) / B. 자기 차례에 받는다(앞 그림만 보고 이어 그려 더 웃기지만 스파이 모드와 겹치고 서버·화면이 커진다).
2. **앞사람 그림 보호** — A. 전체 지우기·되돌리기는 자기 구간만(권장) / B. 전부 자유(통째로 지우는 장난 가능).
3. **최소 인원** — A. 3명, 2명 방은 카드 비활성(권장) / B. 2명도 허용(주자 1 + 맞히는 1, 릴레이가 성립하지 않아 비권장).
4. **이름·카드 문구** — 권장: 카드 이름 "이어 그리기", 설명 "한 그림을 돌아가며 이어 그려요".
5. **주자 점수** — 권장: 주자 각자 `200 × 맞힌 비율`(초안, 출시 뒤 조정). 정답자 대비 너무 크거나 작다고 느끼면 숫자만 바꾸면 된다.
6. **구현 시점** — 권장: 11월 구현(로드맵 그대로), 10/13~10/26에 GO. 방송·스트리머 일정이 앞당겨지면 R1~R3만 먼저.
