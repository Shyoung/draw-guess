## 1. 한 줄 요약 · 누구의 어떤 상황
**여러 명이 한 그림을 차례로 이어 그리고, 순서의 마지막 한 명이 그 그림을 보며 맞히는 모드.** 뒤 주자는 자기 차례가 올 때까지 제시어를 모르고 앞 그림을 보며 "이게 뭐지?"를 추측하다가, 차례가 오면 제시어를 받아 이어 그린다. 3~6명 방에서 "누가 이상하게 이어 그렸냐"로 웃는 상황을 위한 것이다.
- 성장 단위(한 방)에서의 이유: ① 방장이 "이어 그리기 할래?"로 링크를 보낼 새 이유 ② 결과 그림이 공동 작품이라 **같이 저장·공유하고 싶어진다**(갤러리 이미지) ③ 전원이 한 번씩 맞히고 n−1번 그려서 **구경만 하는 사람이 없다**.

## 2. 목표 지표
- 북극성(완료된 게임 수)에는 "참여 밀도가 높아 끝까지 간다"로 기여. 측정은 기존 `game_completed`의 `mode`·`players`·`turns`·`durationSec`·`bytesOut`으로 하고 **새 지표 이벤트는 만들지 않는다.** 출시 2주간 `mode=relay`의 완료율(`game_started` 대비 `game_completed`)과 `players` 분포, 같은 방의 재시작(`gamesPlayed`)을 classic과 비교. 목표 숫자는 `[측정 뒤 확정]`.

## 3. 규칙과 화면 (classic과 다른 점만)
**턴 구조 — 라운드 개념이 없다.** 게임 시작 시 참가 순서가 정해지고, **한 문제마다 순서가 한 칸씩 앞으로 밀린다.** 각 문제에서 순서의 **마지막 사람이 맞히는 사람**, 나머지가 앞에서부터 주자다. **모두가 한 번씩 맞히면(n문제) 게임이 끝난다.**

| 예: A,B,C | 주자(순서대로) | 맞히는 사람 |
|---|---|---|
| 1번 문제 | A → B | C |
| 2번 문제 | B → C | A |
| 3번 문제 | C → A | B |

4명이면 4문제, 주자 3명(ABC→BCD→CDA→DAB의 앞 3명). 주자 수는 항상 n−1이다.

### 3-1. 제시어는 "조합"이다 (맞히는 사람이 실시간으로 보기 때문)
맞히는 사람은 처음부터 그림을 실시간으로 보고 아무 때나 맞힐 수 있다. 제시어가 단어 하나면 첫 주자가 잘 그리는 순간 문제가 끝나 뒤 주자가 그릴 일이 없다. 그래서 **제시어를 요소 2~3개의 조합**으로 낸다. 요소를 다 그리려면 주자 여러 명이 필요하고, 맞히는 사람은 요소를 하나씩 맞혀 가며 남은 요소를 기다린다.

| 항목 | 규칙 |
|---|---|
| 형식 | 요소 나열 `고양이 · 축구 · 바다`. 문장("바다에서 축구하는 고양이")이 아니라 나열이다 — 조사·어순 문제가 없고 판정이 쉽다. 주자는 나열을 보고 알아서 장면을 만든다 |
| 요소 수 | `max(2, min(주자 수, 3))`. 3명 방(주자 2) → 2개, 4명 이상 → 3개. ALLOW_SOLO 서버의 2명 방(주자 1)도 2개 |
| 생성 | 기본 사전의 카테고리 조합 템플릿에서 뽑는다(초안: 2개 `동물+행동·놀이·행사` `동물+음식` `직업·사람·캐릭터+탈것` `동물+장소·자연` `직업·사람·캐릭터+사물` · 3개 `동물+사물+장소·자연` `직업·사람·캐릭터+탈것+장소·자연` `동물+음식+행동·놀이·행사`). 방 설정 `categories`에 모두 들어 있는 템플릿만 쓰고, 맞는 템플릿이 없으면 켜진 카테고리에서 서로 다른 카테고리로 무작위 조합. `customWords`는 요소 풀에 섞이고 `customWordsOnly`면 사용자 단어끼리 조합 |
| 후보 | 첫 주자에게 조합 `wordCount`개를 보여 주고 하나를 고른다(기존 choosing 15초, 시간 초과 시 첫 후보) |
| 마스크 | 요소별 `_ _ _ · _ _ · _ _`. 카테고리 힌트는 없다 |
| 판정 | 맞히는 사람의 채팅을 정규화한 뒤 **모든 요소가 들어 있으면 정답**(순서·조사 무관, 예: "바다에서 고양이가 축구해" ✓). 일부만 맞으면 보낸 사람에게만 `"3개 중 1개 맞았어요!"`(기존 `close` 채널)와 함께 맞힌 요소가 마스크에서 글자로 공개된다(본인만). 요소 하나만 근접(Levenshtein ≤ 1)해도 `close` |

### 3-2. 진행
| 항목 | 규칙 |
|---|---|
| 화면 배치 | **주자 전원은 그리기 화면**(툴바·캔버스·주자 채팅). 자기 구간이 아니면 툴바가 잠기고 캔버스는 실시간으로 보인다. **맞히는 사람은 맞히기 화면**(실시간 캔버스·채팅·힌트 버튼) |
| 제시어 공개 | 첫 주자: 고른 순간부터 문제 끝까지. 뒤 주자: **자기 구간이 시작될 때 받고, 그 뒤로는 계속 보인다**(이미 알았으므로). **차례가 오기 전에는 맞히는 사람과 같은 마스크만 본다**(미리 준비 못 함) |
| 구간 시간 | **한 명당 그리는 시간 = 게임 설정 `drawTime`**, 이 모드의 기본 20초. 경계는 고정이고 타이머는 끊기지 않는다. 문제 전체 시간 = `drawTime × 주자 수` |
| 맞히기 | 첫 주자의 구간이 시작되는 순간부터 **마지막 주자의 구간이 끝날 때까지** 아무 때나. 별도 정답 시간은 없다. 정답이 나오면 문제는 즉시 끝난다(아직 안 그린 주자는 건너뜀) |
| 힌트 | 자동 힌트 없음. **맞히는 사람이 "초성 힌트" 버튼을 누르면** 미공개 글자 하나의 초성이 공개된다(기존 규칙). 최대 횟수 = 설정 `hints`(카드 프리셋 3). 누를 때마다 정답 점수가 깎인다(아래). 마스크는 맞히는 사람과 아직 차례 전인 주자에게 같이 갱신된다 |
| 채팅 | 주자 채팅은 **주자끼리만** 보인다(현재·지난·다음 주자 모두, 추측·조율용. 기존 정답자 전용 채널 재사용). 맞히는 사람의 채팅은 **방 전체**에 보이고 정답 판정 대상이다(주자들이 오답을 보며 즐긴다) |
| 캔버스 | 같은 캔버스를 이어 쓴다. **전체 지우기·되돌리기는 자기 구간에 그린 것만** 지운다(앞사람 그림 보호). 지우개·채우기 덧칠은 허용 |
| 점수 | 맞히는 사람: `round((100 + 300 × 남은 전체 시간 / 전체 시간) × (1 − 0.25 × 힌트 사용 수))`, 최소 50. 주자: 정답이 나온 시점까지 **구간을 가진 주자**(현재 주자 포함) 각 200, 아직 안 그린 주자 0, 못 맞히면 전원 0(초안 — 출시 뒤 조정) |
| 끝 | n문제가 끝나면 `game:over`. `rounds` 설정은 쓰지 않는다(설정 화면에서 숨김). 표시는 "문제 i/n" |
| 인원 | 최소 **3명**(2명 방은 카드 비활성 "3명부터 할 수 있어요"). 상한은 §7-2 |
| 참가·이탈 | 게임 시작 때 순서가 고정된다. 중간 참가자는 관전(맞히기 화면·채팅 판정 없음)하고 다음 게임부터. 끊김은 기존 유예(`RECONNECT_GRACE_MS`·`DRAWER_GRACE_MS`) 안에서 복귀하면 자기 구간 남은 시간만큼 그린다. 구간을 놓치면 그 구간은 비워 두고 경계에서 다음 주자로 넘어간다. 맞히는 사람이 나가면 그 문제는 점수 없이 넘어가고(`guesserLeft`), 접속 인원이 3명 미만이 되면 기존 `notEnoughPlayers` |

**화면**
- 상단 띠(전원): "🖍 ○○님 (2/3) · 다음 △△님" + 구간 타이머, 오른쪽에 문제 전체 타이머. 맞히는 사람 아바타는 "🎯"로 구분.
- **내 차례가 되는 순간** 전체 화면 배너 "내 차례! 20초"와 진동(모바일), 제시어가 크게 뜬다. 구간이 끝나면 툴바가 잠기고 "다음은 △△님".
- 맞히는 사람 화면: 마스크 아래 "초성 힌트 (남은 2회 · −25%)" 버튼. 부분 정답이면 맞힌 요소가 글자로 바뀐다.
- 모바일: 주자는 기존 그리기 배치(툴바 잠금 상태 포함), 맞히는 사람은 기존 맞히기 배치. 한 게임 안에서 역할이 문제마다 바뀌므로 배치 전환이 깜빡이지 않는지 확인 필요.

## 4. 프로토콜·서버·클라이언트 영향
**먼저 [PROTOCOL.md](../../PROTOCOL.md)를 고친다.**
- `settings.mode`에 `'relay'` 추가. relay에서의 의미 변화: `drawTime` = 한 명당 구간 시간, `hints` = 맞히는 사람이 누를 수 있는 최대 힌트 횟수, `rounds`·`hintEndAt` = 무시(`totalRounds` = n). `wordCount`·`categories`·`customWords`는 그대로(조합 후보에 적용).
- 제시어 표현: 서버는 `word`(표시용 `"고양이 · 축구"`)와 `parts:[…]`(판정용)를 함께 갖는다. 갤러리·`turnEnd`·그림 보관은 `word` 문자열이라 그대로 동작.
- `game:drawing`에 `relay: { order:[id…], guesserId, legIndex, legCount, legTime, totalTime, hintsUsed, hintsMax }` 추가. `word`는 **현재·지난 주자에게만**, 나머지는 `wordMask`.
- 새 이벤트 `game:baton { legIndex, legCount, drawerId, drawerName, legTimeLeft, word? }` — 구간 전환 때 방 전체(`word`는 새 주자에게만). 서버는 앞 주자의 열린 획을 닫고(`draw:end` 중계) `drawerId`를 교체한 뒤 `room:state`.
- 새 이벤트 C→S `hint:request` — 맞히는 사람, drawing 중, 남은 횟수 안에서. 응답은 기존 `game:hint`(마스크를 보는 사람 전원 = 맞히는 사람 + 차례 전 주자)에 `hintsUsed` 필드 추가.
- 부분 정답: 보낸 사람에게 `chat:message kind:'close'`(문구 `"3개 중 1개 맞았어요!"`) + 본인만 `game:hint`로 맞힌 요소가 글자로 공개된 마스크. 나머지에게는 일반 채팅으로.
- `game:timer`에 relay일 때 `legTimeLeft` 추가(`timeLeft`는 문제 전체 남은 시간 — 점수 계산과 같은 값).
- `room:state`: `drawerId` = 현재 구간 주자, `relay: { order, guesserId, legIndex, legCount }` 추가(relay 아닐 땐 null). `players[].isDrawing`은 현재 주자만 true.
- `game:turnEnd.reason`에 `'guesserLeft'` 추가. `game:over.gallery[]` 항목에 `drawerIds[]`·`guesserId` 추가(기존 `drawerId` = 첫 주자, 하위 호환). 그림 보관 조건: `drawerIds`에 내가 있으면 저장(PROTOCOL "로그인" 절 수정).
- 서버 `server/words.js`: 조합 템플릿·`pickCombos(settings, count, partCount)`·요소 마스크·요소 판정(`matchParts(text, parts)` → 맞힌 요소 인덱스). `server/game.js`: `MODES`, 턴 순서·`nextTurn`(순서 밀기·n문제 종료), `beginChoosing/beginDrawing`(첫 주자 선택·구간 타이머·공개 범위), `tick`(경계 `baton`), `handleDraw`(구간 시작 시점의 ops 길이를 기록해 그 앞은 undo/clear 불가), `handleChat`(주자 채널·부분 정답), `hint:request`, `onCorrectGuess`·`endTurn`(점수·종료), 끊김·퇴장, 스냅샷 저장·복원(구간 상태·힌트 수·부분 정답 포함).
- 클라이언트(`public/client.js`, `style.css`, `index.html`): 모드 카드, 설정(한 명당 시간·최대 힌트 라벨, 라운드·힌트 시점 숨김), 상단 띠·바통 배너·툴바 잠금, 구간마다 `isDrawer()` 전환(`state.drawerId` 기준이라 대부분 자동)과 주자 전원의 그리기 배치 유지(`data-role`을 주자/맞히는 사람으로), 제시어·마스크 표시, 힌트 버튼, 부분 정답 표시, 주자 채팅 스타일, 공동 작가 갤러리.
- 건드리지 않는 것: 캔버스 좌표·op 형식, 힌트 초성 규칙, 인증, 다른 모드의 동작.

## 6. 위험과 대안
- **조합이 어색하다**("바퀴벌레 · 결혼식 · 사막"): 템플릿을 소수로 시작하고 어색한 카테고리(신체·건강, 나라·도시)는 템플릿에서 뺀다. 출시 뒤 운영자 관찰로 템플릿을 조정한다. 방장은 `customWords`로 자기 요소를 넣을 수 있다.
- **첫 주자가 요소를 다 그려 버린다**: 20초라 보통 한두 개가 한계. 그래도 일찍 맞히면 뒤 주자는 0점 — "빨리 끝나서 다음 문제"로 넘어가니 게임 자체는 문제없다. 점수 불만이 나오면 주자 점수를 전원 배분으로 바꾼다(숫자만 조정).
- **대인원에서 길어진다**: 문제 하나 ≈ (n−1)×20초 + 선택 15초 + 종료 5초. 4명 ≈ 80초×4 ≈ 5분, 6명 ≈ 120초×6 ≈ 12분, 8명 ≈ 160초×8 ≈ 21분. 상한 6명 권장(§7-2). 구간 시간은 설정으로 줄일 수 있다.
- **주자끼리 스포**: 앞 주자가 채팅으로 뒤 주자에게 제시어를 알려줄 수 있다. 사회적 규칙에 맡기고(재미 요소이기도 함) 맞히는 사람에게는 서버가 주자 채팅을 보내지 않는다.
- **트롤(그림을 망침)**: 앞 그림을 통째로 못 지우고(구간 보호), 덧칠은 허용이라 웃음으로 본다. 문제가 되면 핸디캡 토글(GAME-MODES 7번)로 해결.
- **모바일 교대 순간**: 구간 끝에 손가락이 캔버스에 있으면 서버가 획을 닫고 이후 입력은 무시. 클라이언트는 `baton` 수신 시 열린 획을 닫는다.
- **재접속·배포 중**: 구간 상태·힌트 수·부분 정답을 스냅샷에 넣는다. 배포 중 게임 보호는 그대로.
- **대역폭(Render 5GB)**: op 중계는 classic과 같다(한 번에 한 명 그림, 받는 사람 수 같음). 추가는 `baton`·`hint` 이벤트뿐이라 무시 가능. 출시 뒤 `bytesOut`으로 확인.
- **점수 밸런스**: 주자 200·힌트 −25%는 초안. 출시 뒤 조정.
