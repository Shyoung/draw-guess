작성 2026-09-30 (수) · 작성: 기획 세션 · 상태: **설계 승인(운영자 GO 09-30, 기획 세션)** · 후보 번호: [GAME-MODES.md](../GAME-MODES.md) 1번

## 1. 한 줄 요약 · 누구의 어떤 상황
**한 사람이 문제를 내고, 여러 명이 그 그림을 차례로 이어 그리고, 마지막 사람이 완성된 그림만 보고 맞히는 모드.** 앞사람이 뭘 그렸는지 모르는 채 이어 그리다 "이게 뭐가 된 거야"로 웃는 3~6명 방을 위한 것이다(전달 게임의 그림판 버전).
- 성장 단위(한 방)에서의 이유: ① 방장이 "이어 그리기 할래?"로 링크를 보낼 새 이유 ② 결과 그림이 공동 작품이라 **같이 저장·공유하고 싶어진다**(갤러리 이미지) ③ 전원이 한 번씩 맞히고 n−1번 그려서 **구경만 하는 사람이 없다**.

## 2. 목표 지표
- 북극성(완료된 게임 수)에는 "참여 밀도가 높아 끝까지 간다"로 기여. 측정은 기존 `game_completed`의 `mode`·`players`·`turns`·`durationSec`·`bytesOut`으로 하고 **새 지표 이벤트는 만들지 않는다.** 출시 2주간 `mode=relay`의 완료율(`game_started` 대비 `game_completed`)과 `players` 분포, 같은 방의 재시작(`gamesPlayed`)을 classic과 비교. 목표 숫자는 `[측정 뒤 확정]`.

## 3. 규칙과 화면 (classic과 다른 점만)
**턴 구조 — 라운드 개념이 없다.** 게임 시작 시 참가 순서가 정해지고, **한 문제마다 순서가 한 칸씩 앞으로 밀린다.** 각 문제에서 순서의 **마지막 사람이 맞히는 사람**, 나머지가 앞에서부터 주자다. **모두가 한 번씩 맞히면(n문제) 게임이 끝난다.**

| 예: A,B,C | 주자(순서대로) | 맞히는 사람 |
|---|---|---|
| 1번 문제 | A → B | C |
| 2번 문제 | B → C | A |
| 3번 문제 | C → A | B |

4명이면 4문제, 주자 3명(ABC→BCD→CDA→DAB의 앞 3명). 주자 수는 항상 n−1이다.

| 항목 | 규칙 |
|---|---|
| 단어 | **첫 주자만 후보 중에서 고른다**(기존 choosing 15초). 이후 주자는 **자기 구간 동안에만 단어를 볼 수 있다**(자기 구간이 끝나면 숨김). 앞 그림을 보며 "이게 뭘까?"를 추측해 이어 그리는 것이 재미 |
| 구간 시간 | **한 명당 그리는 시간은 게임 설정의 `drawTime`**, 이 모드의 기본 20초. 경계는 고정이고 타이머는 끊기지 않는다 |
| 맞히는 사람 | 주자들이 그리는 동안은 **그림을 볼 수 없다**("친구들이 그리는 중… 지금 ○○님 (2/3)"). 마지막 주자의 구간이 끝나면 **완성된 그림이 한 번에 공개**되고 정답 시간(`guessTime`, 새 설정, 기본 30초)이 시작된다 |
| 주자가 아닌 사람 | 앞 주자들(이미 그린 사람)과 뒤 주자들(아직 안 그린 사람)은 캔버스를 실시간으로 본다. 뒤 주자는 단어를 모른 채 앞 그림으로 짐작한다 |
| 채팅 | 주자들끼리의 채팅은 열려 있고(추측·조율), **맞히는 사람에게는 그 문제가 끝날 때까지 보이지 않는다.** 맞히는 사람의 채팅만 정답 판정 |
| 힌트 | 정답 시간 기준으로 기존 `hints`·`hintEndAt` 규칙을 그대로 적용(맞히는 사람에게만 초성 공개). 이어 그리기 카드 프리셋은 hints 2 |
| 캔버스 | 같은 캔버스를 이어 쓴다. **전체 지우기·되돌리기는 자기 구간에 그린 것만** 지운다(앞사람 그림 보호). 지우개·채우기 덧칠은 허용 |
| 점수 | 맞히는 사람: classic 공식(`guessTime` 기준 남은 시간). 주자: **맞히면 각자 200, 못 맞히면 0**(초안 — 출시 뒤 조정). 문제는 맞히는 사람이 정답을 내면 즉시 끝난다 |
| 끝 | n문제가 끝나면 `game:over`. `rounds` 설정은 이 모드에서 쓰지 않는다(설정 화면에서 숨김). 표시는 "문제 i/n" |
| 인원 | 최소 **3명**(2명 방은 카드 비활성 "3명부터 할 수 있어요"). 권장 **6명까지**(§6) |
| 참가·이탈 | 게임 시작 때 순서가 고정된다. 중간 참가자는 관전하고 다음 게임부터. 끊김은 기존 유예(`RECONNECT_GRACE_MS`·`DRAWER_GRACE_MS`) 안에서 복귀하면 자기 구간 남은 시간만큼 그린다. 구간을 놓치면 그 구간은 비워 두고 경계에서 다음 주자로 넘어간다. 맞히는 사람이 나가면 그 문제는 점수 없이 넘어가고, 접속 인원이 3명 미만이 되면 기존 `notEnoughPlayers` |

**화면**
- 상단 띠: "🖍 ○○님 (2/3)" + 다음 주자. 주자 아바타는 기존 출제자 강조.
- **내 차례가 되는 순간** 전체 화면 배너 "내 차례! 20초"와 진동(모바일), 단어가 크게 뜬다. 구간이 끝나면 툴바가 잠기고 단어가 사라진다.
- 맞히는 사람 대기 화면은 공책 그림 스타일의 "그리는 중" 안내와 주자 진행 띠만 있다(그림 없음). 공개 순간 캔버스가 채워지는 연출.
- 모바일: 기존 그리기 배치(내 차례)·맞히기 배치(그 외)를 구간마다 전환. 확인 필요: 구간 전환 때 키보드·툴바가 깜빡이지 않는지.

## 4. 프로토콜·서버·클라이언트 영향
**먼저 [PROTOCOL.md](../../PROTOCOL.md)를 고친다.**
- `settings.mode`에 `'relay'`, `settings.guessTime`(15..90, 기본 30) 추가. `drawTime`은 relay에서 **한 명당 구간 시간**이라고 PROTOCOL에 명시. 서버 clamp. relay의 `rounds`는 무시(`totalRounds` = n).
- `game:drawing`에 `relay: { order:[id…], guesserId, legIndex, legCount, legTime }` 추가. `word`·`category`는 **현재 구간 주자에게만**(맞히는 사람에게는 `wordMask`만). 구간 경계마다 공개 대상이 바뀐다.
- 새 이벤트 `game:baton`:
  - 구간 전환: `{ stage:'draw', legIndex, legCount, drawerId, drawerName, legTimeLeft, word? }` (`word`는 새 주자에게만). 서버는 앞 주자의 열린 획을 닫고(`draw:end` 중계) `drawerId`를 교체한 뒤 `room:state`를 보낸다.
  - 정답 시간 시작: `{ stage:'guess', guesserId, timeLeft, wordMask, wordLength }` + 맞히는 사람에게만 `draw:sync { ops }`(완성 그림).
  - catch-up(재접속)에도 같은 정보를 보낸다.
- **맞히는 사람에게는 `draw:*`를 구간 동안 중계하지 않는다**(서버가 제외 — 클라이언트 숨김이 아니라 전송 차단). 새로고침해도 못 본다.
- `room:state`: `drawerId` = 현재 구간 주자(정답 시간엔 `null`), `players[].isDrawing` 그대로, `relay: { order, guesserId, stage, legIndex }` 추가(relay 아닐 땐 null).
- `game:timer`의 `timeLeft`는 현재 구간(또는 정답 시간)의 남은 초. 점수·힌트는 정답 시간 기준.
- `game:turnEnd.reason`에 `'guesserLeft'` 추가. `game:over.gallery[]` 항목에 `drawerIds[]`·`guesserId` 추가(기존 `drawerId` = 첫 주자, 하위 호환). 그림 보관 조건: `drawerIds`에 내가 있으면 저장(PROTOCOL "로그인" 절 수정).
- 서버(`server/game.js`): `MODES`, 턴 순서·`nextTurn`(순서 밀기·n턴 종료), `beginChoosing/beginDrawing`(첫 주자만 선택·구간 타이머), `tick`(경계 `baton`·정답 시간 전환), `handleDraw`(자기 구간 이전 ops 보호 — 구간 시작 시점의 ops 길이 기록), `handleChat`(주자 채널·맞히는 사람 차단), `onCorrectGuess`·`endTurn`(점수·종료), 끊김·퇴장, 스냅샷 저장·복원(구간 상태 포함).
- 클라이언트(`public/client.js`, `style.css`, `index.html`): 모드 카드, 설정(한 명당 시간·정답 시간 표시, 라운드 숨김), 상단 띠·바통 배너, 구간마다 `isDrawer()` 전환(`state.drawerId` 기준이라 대부분 자동), 맞히는 사람 대기 화면·공개 연출, 주자 채팅 스타일, 공동 작가 갤러리.
- 건드리지 않는 것: 캔버스 좌표·op 형식, 정답 판정 함수, 힌트 계산 함수, 인증.

## 6. 위험과 대안
- **대인원에서 시간이 길어진다**: 주자는 n−1명이라 문제 하나 ≈ (n−1)×20초 + 선택 15초 + 정답 30초 + 종료 5초. 4명 ≈ 110초×4문제 ≈ 7분, 6명 ≈ 150초×6 ≈ 15분, 8명 ≈ 190초×8 ≈ 25분. **권장 6명까지**, 7명 이상이면 카드 비활성("6명까지 할 수 있어요")이 기본안(§7-1). 구간 시간은 설정으로 줄일 수 있다.
- **맞히는 사람이 한참 대기**: 그림을 못 보니 n이 클수록 지루하다. 대기 화면에 진행 띠와 주자 이름을 띄워 지루함을 줄인다.
- **단어 스포**: 앞 주자가 채팅으로 뒤 주자에게 답을 알려줄 수 있다 — 주자 채팅은 사회적 규칙에 맡긴다(재미 요소이기도 함). 맞히는 사람에게만 새지 않게 서버에서 막는다.
- **트롤(그림을 망침)**: 앞 그림을 통째로 못 지우고(구간 보호), 덧칠은 허용이라 웃음으로 본다. 문제가 되면 핸디캡 토글(GAME-MODES 7번)로 해결.
- **모바일 교대 순간**: 구간 끝에 손가락이 캔버스에 있으면 서버가 획을 닫고 이후 입력은 무시. 클라이언트는 `baton` 수신 시 열린 획을 닫는다.
- **재접속·배포 중**: 구간 상태를 스냅샷에 넣는다. 배포 중 게임 보호는 그대로. 맞히는 사람이 새로고침해도 공개 전 그림이 안 보인다(서버 차단).
- **대역폭(Render 5GB)**: op 중계는 classic과 같은 크기(한 번에 한 명 그림)이고 맞히는 사람은 오히려 덜 받는다. 추가는 공개 시 `draw:sync` 한 번(맞히는 사람 1명)뿐. 출시 뒤 `bytesOut`으로 확인.
- **점수 밸런스**: 주자 200은 초안. 출시 뒤 조정.
