## 0. 한 페이지 요약

- **목표**: 최대한 많은 사람이 이뭔그를 즐기게 한다. 성과는 매출이 아니라 **완료된 게임 판수 · 방 수 · 방당 인원 · 다시 방을 여는 방장 수**로 본다.
- **성장 단위는 "한 방"(친구 3~8명)이다.** 방장 한 명이 카톡방에 링크를 올리는 순간이 광고고, 받은 사람이 눌러서 10초 안에 그림을 보면 그게 전환이다. 그래서 첫 달 우선순위는 이렇다.
  1. **링크 미리보기(OG) 만들기**: 지금은 OG 태그가 하나도 없다 [확인: `public/index.html`]. 카톡에 링크가 제목만 덩그러니 뜬다. 광고비가 0원인 게임에서 이게 가장 큰 광고판이다.
  2. **최소 지표 로깅**: 지금은 방이 몇 개 생기는지도 알 수 없다(`/healthz`의 현재 방 수만 보인다 [확인]). 판수·인원·유입 경로 3가지부터 남긴다.
  3. **인프라 한도 확인**: Render 무료 플랜은 **작업공간(workspace) 하나당 월 750시간, Hobby 아웃바운드 대역폭 월 5GB**다 [확인: Render 문서]. 입소문이 나기 전에 한도 때문에 서버가 한 달 내내 꺼지는 일부터 막아야 한다(6장).
  4. **씨앗 채널**: 운영자 본인 단톡방 → 개발자 커뮤니티(GeekNews Show, 디스콰이엇, 디시 인디 개발 갤) → 참가자가 스스로 올리는 그림·영상(운영자 계정 숏폼은 안 한다, 0-1) → 소형 스트리머 합방 → 디스코드·동아리·회사 송년회 순서로 넓힌다.
- **하지 않는 것**: 커뮤니티 도배, 개발자 신분 숨긴 바이럴, 가짜 후기, 지인에게 추천 부탁, 조작된 수치. 이 중 하나만 들켜도 한국 커뮤니티에서는 그대로 박제된다 [확인: 디시 인디게임 갤 공지, 펨코 통합 규정, GeekNews Show 운영 원칙].

### 0-1. 운영 원칙 추가 (2026-09-29, 운영자 결정)
- **운영자 명의 인스타·틱톡·쇼츠 계정을 만들어 직접 홍보하지 않는다.** "회사가 밀어주는 게임"이 아니라 "친구가 하길래 해 봤다"로 체감돼야 한다.
- 그래서 운영자가 직접 하는 노출은 **① 신분을 밝힌 메이커 글 한 번(GeekNews·디스콰이엇·디시 인디 갤)** ② 스트리머·디스코드·동아리에 개별 제안 ③ 정기 공개 방 진행, 이 셋으로 제한한다. 나머지 확산은 **참가자와 스트리머가 자기 계정에 올리는 것**에 맡긴다.
- 운영자의 역할은 "올리고 싶어지는 결과물"을 만드는 것이다: 갤러리 이미지에 브랜드·주소(F5), 공유 버튼(F3), 스트리머 모드(F4), 시즌 단어 세트(F8). 이 순서로 개발 우선순위를 올린다.
- 원칙 8장은 그대로다: 신분 숨긴 바이럴·지인 댓글 부탁·여러 계정은 "자연스러워 보이게 하는 것"이 아니라 조작이다. 입소문은 **진짜로** 나야 한다.

## 1. 포지셔닝 · 핵심 메시지 · 성장 루프

### 1-1. 한 줄 포지셔닝
> **"카톡에 링크 하나 던지면 10초 뒤에 다 같이 그리고 있는, 한국어 그림 맞히기."**

비교 맥락 (알고 쓰자):
- **캐치마인드** 향수: 넷마블 '쿵야 캐치마인드'가 2023-05-23에 서비스를 종료했다 [확인: [한국경제](https://www.hankyung.com/article/202309017163Y), [네이트뉴스](https://m.news.nate.com/view/20230222n29603)]. "캐치마인드 같은 거 없나?" 하는 수요는 남아 있다 [추정: [클리앙 문의글](https://www.clien.net/service/board/kin/18797010) 같은 글이 있다].
- **skribbl.io**: 설치·가입 없이 하는 웹게임이고 한국어도 지원한다. 다만 한국어 제시어에 번역 오류나 어색한 단어가 섞인다는 평이 있다 [확인: [나무위키 Skribbl.io](https://namu.wiki/w/Skribbl.io)]. → 우리 강점은 **직접 고른 한국어 기본 단어 약 3,000개(13개 분류)** [확인: `server/words.js` 집계 3,023개]와 **초성 힌트**다.
- **Gartic Phone**: 한국에서는 2021년 7월부터 방송인들이 많이 하면서 떴고, 지금은 한창때보다 식었지만 인원 제한이 사실상 없어서 대규모 합방이나 시청자 참여 콘텐츠로 여전히 쓰인다 [확인: [나무위키 Gartic Phone](https://en.namu.wiki/w/Gartic%20Phone)]. → 스트리머 시장에서 우리 약점은 **최대 12명** [확인: `server/index.js` MAX_PLAYERS=12].
- **디스코드 Sketch Heads / Gartic Phone 액티비티**: 디스코드 음성 채널 안에서 바로 실행된다 [확인: [Discord Sketch Heads FAQ](https://support-apps.discord.com/hc/en-us/articles/26502296609943-Sketch-Heads-FAQ), [Discord 앱 디렉터리](https://discord.com/discovery/applications/1546188029884899338)]. 디스코드에서 우리 차별점은 한국어 단어와 초성 힌트, 모바일 카톡 공유다.
- **치즈 스케치**: 치지직 채팅과 연동되는 드로잉 퀴즈다. 시청자가 채팅으로 정답을 치면 자동으로 채점되고, SOOP·YouTube 동시 연동(BETA)도 된다 [확인: [cheese-sketch.art](https://cheese-sketch.art/), [X 소개글](https://x.com/virtual_lab101/status/2052228017141993740?lang=ko)]. → **"시청자 수백 명 참여" 판에서 정면으로 붙지 않는다.** 우리는 "스트리머끼리 합방"과 "소형 방송 + 시청자 10명 안팎"을 노린다.

### 1-3. 성장 루프 (방장 → 카톡 링크 → 참가 → 다음 방장)

```
 ① 방장이 방 만들기 (0원 광고비의 유일한 "구매" 순간)
        │  [병목 A] 링크를 보내고 싶은가?  → 초대 문구 복사, 공유 버튼, 예쁜 미리보기
        ▼
 ② 카톡 단톡방에 링크 (OG 미리보기 = 광고 소재)
        │  [병목 B] 눌러 보고 싶은가?  → OG 이미지/제목, "OO방에 초대받음" 문구
        ▼
 ③ 참가자: 링크 → 닉네임 → 대기실 (10초 목표)
        │  [병목 C] 10초 안에 들어오는가? → 콜드스타트 0, 게스트 기본, 초대 카드 바로 "참가하기"
        ▼
 ④ 게임 1판 (5~10분) → 웃긴 그림 → 갤러리
        │  [병목 D] 한 판 더? 캡처 공유?  → 대기실로 돌아가면 설정 유지, 갤러리 한 장 저장에 로고+주소
        ▼
 ⑤ 참가자 중 누군가 "다음엔 우리 과방/가족방에서 하자" → 새 방장 (루프 재시작)
        │  [병목 E] 주소를 기억하는가? → 짧은 주소/도메인, 홈 화면 추가, 갤러리 이미지 속 주소
        └──────────────────────────────▶ ①
```

- **루프 지표**: 방장 1명당 참가자 수(목표 평균 3.5명 이상), 방당 판수(1.8판 이상), **참가자 → 방장 전환율**(목표 90일 내 10%) [제안 · 측정은 6장].
- 현재 상태 [확인]: ③은 잘 되어 있다(초대 카드 + "이 방에 참가하기"). ①②에는 OG도 공유 버튼도 없다(링크 복사만 있다). ④의 개별 그림 PNG에는 "이뭔그 — 이게 뭔 그림인데?" 글자가 들어가지만 **주소가 없고**, 한 장 모아 저장에는 브랜드도 주소도 없다 [확인: `client.js` 785~810줄 부근].

### 6-2. 최소 지표 로깅 스펙 (개발 작업으로 번역)
원칙: **닉네임·IP·채팅 내용은 남기지 않는다.** 지금 서버는 방을 만들 때 로그에 닉네임을 찍는다 [확인: `server/index.js` 369줄 `created by ${name}`] → 이것도 빼기를 권한다.

1. **이벤트 한 줄 JSON 로그** (`console.log('[metric] ' + JSON.stringify(...))`):
   | 이벤트 | 필드 |
   |---|---|
   | `room_created` | ts, room(코드), ref, loggedIn(bool) |
   | `player_joined` | ts, room, via(`link` \| `code`), ref, midGame(bool), size(참가 뒤 인원) |
   | `game_started` | ts, room, mode, players, rounds, drawTime, customWords(bool) |
   | `game_completed` | ts, room, mode, players, turns, durationSec, galleryTrimmed(bool) |
   | `game_aborted` | ts, room, players, turnsPlayed, reason(`host` \| `notEnoughPlayers`) |
   | `room_closed` | ts, room, gamesPlayed, peakPlayers, lifetimeSec |
   | `room_full_rejected` | ts, room (12명 제한에 걸린 횟수) |
2. **일별 집계 카운터**: Render Hobby 로그 보관이 짧으므로(7일 [추정: [Render 비용 안내 글](https://render.com/articles/how-much-does-cloud-application-hosting-cost-for-small-businesses) 검색 요약 기준, 대시보드에서 확인 필요]) 이미 있는 Key Value에 `stats:YYYY-MM-DD` 해시로 누적(방 생성, 게임 시작·완료, 참가자 수 합, ref별 방 생성). 데이터가 작아서 무료 25MB로 충분하다.
3. **조회 경로**: `/admin/stats?key=<환경변수 비밀값>` → 최근 30일 표(JSON). 공개 `/healthz`에는 넣지 않는다.
4. **유입 경로 `?ref=`**: `https://…/?ref=gn`처럼 채널별 링크를 쓴다. 클라이언트가 sessionStorage에 저장했다가 `room:create`/`room:join` 페이로드에 `ref`를 붙인다. **PROTOCOL.md에 필드 추가가 필요하다**(선택 필드라 호환성 문제 없음). 초대 링크에는 원래 방장의 ref를 이어 붙이지 않는다(초대 = `via:link`로 따로 센다).
   - ref 코드: `gn`(GeekNews), `dq`(디스콰이엇), `dc`(디시), `yt`/`ig`/`tt`(타인이 올린 영상 설명란에 링크를 넣어 줄 때만), `st-<이름>`(스트리머), `dsc-<서버>`, `org-<회사/동아리>`, `open`(정기 공개 방)
5. **대역폭 계측**: 게임별 서버 송신 바이트(socket.io 패킷 크기 합)를 `game_completed`에 `bytesOut`으로 남긴다. 6-3의 5GB 한도 판단에 필수다.
6. (선택, 개인정보 처리방침 수정 뒤) **재방문 방장 측정**: 브라우저 재접속 토큰의 **소금 친 해시 앞 10자**만 남기면 "7일 안에 다시 방을 연 방장", "참가자 → 방장 전환"을 셀 수 있다. 지금 처리방침은 "게스트 토큰은 60초 유예 뒤 서버에서 삭제", "행태 분석 목적 쿠키 없음"이라고 적혀 있다 [확인: `/privacy` 1·6항]. → **처리방침에 '익명 이용 통계' 문구를 넣기 전에는 하지 않는다.**
